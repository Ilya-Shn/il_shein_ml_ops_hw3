# Переобучение антифрода в Airflow

Kafka `transactions` → CatBoost CPU → Kafka `scores` → PostgreSQL. Streamlit отправляет CSV и показывает результаты. Airflow и скоринг используют общий каталог `runtime/models`, размеченная витрина хранится в месячных Parquet в `runtime/mart`.

## Запуск

Нужны Docker Compose v2, около 6 ГБ свободной памяти, порты 8081, 8082, 8503. Скачайте `train.csv` и `test.csv` из [соревнования](https://www.kaggle.com/competitions/teta-ml-1-2025/data), приняв правила Kaggle.

```bash
git clone https://github.com/Ilya-Shn/il_shein_ml_ops_hw3.git
cd il_shein_ml_ops_hw3
mkdir -p data runtime
```

Положите оба CSV в `data/`:

```bash
docker compose up -d --build --wait
```

- Airflow: http://localhost:8081, `admin` / `admin`.
- Отправка транзакций и результаты: http://localhost:8503.
- HTML-отчёты DQ: http://localhost:8082, последний — http://localhost:8082/latest.html.

Все три DAG включены и запускаются каждые 5 минут, `catchup=False`. Для ручного запуска откройте DAG и нажмите ▶ → Trigger DAG. Сначала запустите `retrain_catboost` и дождитесь зелёных задач: до первой публикации скоринг ждёт модель. Затем можно отправлять `examples/test.csv` или CSV соревнования через Streamlit. База и Kafka находятся во внутренней сети Compose.

## DAG и модель

`retrain_catboost`: `prepare → fit → evaluate → publish`. Окно — строго 3 последовательных календарных месяца, первые 2 — train, последний — test. Начальное окно — первые три месяца CSV. После публикации окно сдвигается ровно на месяц. Если следующего месяца нет, запуск пропускается.

Собственный препроцессинг общий для обучения и скоринга: исходные категории CatBoost, логарифмы суммы и населения, признаки пропусков, синус/косинус часа, выходной день, расстояние по координатам. Кодирования по target нет. Модель обучается фиксированные 80 итераций на CPU без подбора по test.

Кандидат и текущая prod-модель оцениваются на одном свежем test-месяце: PR-AUC (average precision) и ROC-AUC. Публикация разрешена, только если обе метрики не ухудшились. Первая модель публикуется без сравнения. В train/test обязательны оба класса. Решение и метрики сохраняются в `runtime/models/*.metrics.json`. Отклонение — успешное завершение DAG без смены prod и указателя; следующий запуск снова рассматривает тот же месяц. При таком отказе поставка продолжает идти независимо; если обучение отстанет на всю глубину истории, очистка завершится ошибкой, сохранив нужные обучению данные.

План и split изолированы по запуску. Сначала сохраняется бинарник, затем одним атомарным `os.replace` фиксируются версия и следующий месяц в `runtime/models/state.json`. Повтор задачи после сбоя использует тот же план и не сдвигает окно повторно. Мутации защищены файловой блокировкой; каждый DAG допускает один активный запуск. Скоринг читает состояние перед каждой транзакцией и загружает новую модель без перезапуска контейнера.

`supply_labeled_batch`: `sample → append → prune`. Выборка 100000 строк из витрины с возвращением переносится в следующий месяц после максимального. Час сохраняется, день ограничивается последним днём нового месяца. История — 36 месяцев относительно максимального месяца. Повтор использует сохранённый батч, атомарно заменяет одну партицию и не дублирует месяц. Поставка и обучение имеют разные указатели: сначала обучение проходит исторические месяцы CSV.

`data_quality`: `check → report`. Проверяет всю витрину: обязательные столбцы, непустой набор, корректное заполненное время, target только 0/1, уникальные непустые row_id, конечные неотрицательные amount и population_city, широты в ±90, долготы в ±180, заполненные категории, глубину 36 месяцев, непрерывность месяцев, оба класса в каждом месяце. HTML записывается в `runtime/reports` даже при нарушениях, после чего задача падает. Это отдельный диагностический DAG.

## Проверка

После ручного запуска `retrain_catboost`:

```bash
ls runtime/models
cat runtime/models/state.json
docker compose exec -T postgres psql -U fraud -d fraud -c 'SELECT transaction_id, score, fraud_flag, model_version FROM scores ORDER BY id DESC LIMIT 10;'
```

Отправьте CSV до и после принятого переобучения. `model_version` в новых строках БД и Kafka `scores` должна совпадать с `active` в `state.json`. Если кандидат отклонён, версия сохраняется. Контракт результата: `transaction_id`, `score`, `fraud_flag` (порог `score > 0.98`) и `model_version`.

Полная автоматическая проверка требует Python 3 на хосте, запускает DAG вручную через API Airflow и ждёт реального выполнения всех трёх DAG по расписанию (до 7 минут). Отправляет 120 строк настоящего `test.csv`, сверяет Kafka, модель и PostgreSQL; дополнительно проверяет сбой публикации, повтор задач, временной split, запрет ухудшения, очистку истории и горячую загрузку модели. Результаты — `results/check.json`.

```bash
python3 tests/check.py
docker compose ps
docker compose logs --tail 30 scorer airflow-scheduler
```

Остановка: `docker compose down`. Данные остаются в volumes и `runtime/`. Для чистого запуска удалите volumes командой `docker compose down -v` и содержимое `runtime/`. Локальные пароли учебные.
